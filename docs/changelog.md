# Changelog

Notable changes to API Workbench, newest first. Downloads for each release are on [GitHub Releases](https://github.com/techieutils/api-workbench/releases).

## 1.0.0

_November 2026_: the first open-source release.

### Requests and responses

- Send HTTP and GraphQL requests with params, headers, JSON, XML, form, multipart, and binary bodies. See [Requests](requests.md).
- **Pretty** previews images, PDFs, audio, video, fonts, and HTML, and formats JSON, XML, and text. Streams are left raw. See [Responses](responses.md#pretty-previews).
- Compare two responses side by side.
- Plain-text or visual [tests](tests.md) run on every send and in collection runs.
- Code snippets in 26 languages, plus clients for [WebSocket, SSE, NDJSON, and gRPC](code-snippets.md#realtime-protocols).
- **Markdown** responses render in the app's theme, and links open in your browser after you confirm. **Hex** and **Base64** views show any body's bytes. See [Responses](responses.md).
- The first box in the URL bar chooses the request type: an HTTP method, each with a line on what it is for, or a live protocol.
- **Format** buttons for mock bodies, specifications, the Docs source, generated code, and history responses. History keeps a snapshot of each response.
- Collections can hold nested folders, each with its own HTTP settings and default authorization. See [Collections](collections.md#folders).
- **TRACE and CONNECT** are in the method box. TRACE is sent without a body and shows the server's echo; CONNECT asks the request's proxy (or the server) for a tunnel to the URL's host and port and shows the answer, such as `407` with the proxy's page, without sending anything through it. See [TRACE and CONNECT](rest-graphql.md#trace-and-connect).
- Socket.IO and MQTT requests have their own colour in the method box, tabs, and lists.
- **Body integrity headers** can use your own header name, with CRC-32, CRC-32C, SHA-1, SHA-256, SHA-512, MD5, XXHash64, XXHash3, or XXHash128, in Base64 or hex. See [Settings](settings.md).

### Interface

- A new select box and confirm dialog across the app, and toasts that are toned, stacked, and dismissible.
- Collection actions menus, moving requests between collections, renaming a collection by double-clicking it, a tab overflow menu, and a [keyboard shortcuts](shortcuts.md) sheet (<kbd>?</kbd>).
- Every pane divider can be dragged. The method, URL, and **Send** stay on one row when the request pane is narrow.
- Optional and secondary settings are grouped in expansion panels.
- [Dev tools](dev-tools.md) above the status bar: Console, Network, Performance, and a real Terminal with tabs, split panes, renaming, and reordering. Shells keep running while the panel is closed, and each terminal can run any installed shell (zsh, bash, sh, fish, PowerShell, Command Prompt, Git Bash, or WSL), with a default you choose.
- [Context menus](interface.md#context-menus) on tabs, explorer rows, lists, table rows, messages, and every editor.
- Request tabs can be renamed by double-clicking and reordered by dragging.
- Rows of tabs and filters that do not fit show scroll arrows only where something is hidden.
- Icons beside the choices in every select box and list.
- Collection, `workspace.json`, and `workspaces.json` files edited outside the app reload into the window.
- Choosing **Collections** after closing every tab opens the active request in a tab again.
- The startup screen follows your theme instead of always being dark.
- Click **Private workspace** in the top bar to see where the workspace is stored, how secrets are encrypted, what is remembered, and what leaves the device.
- The **Overview** shows today's activity: requests sent and their success rate, and the median and p95 response time. Its welcome banner takes less room.
- The **Overview** links everywhere it points: counts open their screens, a recent send opens in History with its response, and every workspace essential — including History and saved responses (**Settings → Privacy**) — goes to where it is managed.
- **Help in Settings:** **Settings → Help** reports a problem on GitHub with your version and system filled in, requests a feature, reports a vulnerability privately, copies your version and system, and opens the documentation, troubleshooting, changelog, and known issues. The command palette has **Help and support** and **Report a problem on GitHub**. See [Support](support.md#from-the-app-or-vs-code).
- **Guides where you work:** each screen — Overview, Environments, History, API specifications, documentation, Runner, Cookies, Interceptor, Credentials, Mock servers, and each Settings section — has a **Guide** button beside its title that opens its page on the documentation site, and the **Scripts**, **Tests**, and **Captures** tabs have a book button beside their heading. **Open documentation** is in the command palette. In VS Code, the request, live request, new request, mock server, runner, specification, environments, credentials, certificates, and test results pages have a **Guide** button too, and the sidebar's welcome text and each walkthrough step link to their part of the VS Code guide on the documentation site. See [Support](support.md#from-the-app-or-vs-code).

### Tags

- **Request tags:** label requests with tags such as `smoke`, `auth`, or `slow`, under the request's name. Tags already used in the workspace are suggested, the explorer search matches them (`#smoke` for one tag exactly), and they are saved in each request's file. See [Tags](requests.md#tags).
- **Collection and folder tags:** a collection or folder can have tags too, from **Tags…** in its menu; every request inside has them as well. The explorer shows them beside the folder's name, and a request shows the tags it has from above before its own. Search, runs, and the command line use both.
- **Filter the explorer by tag:** a **Tags** bar under the explorer's search shows only the requests with the tags you click — or hides them, clicked again — together with the search. It works as the Runner's tag filter does.
- **Tags in the Docs screen:** a **Tags** bar documents only the requests with the tags you choose — in the reference and in every specification, copied or downloaded — and each OpenAPI operation now lists the request's tags after the collection's name. `collection docs --tag` does the same from the command line.
- **Tags in workspace search:** <kbd>⌘</kbd>+<kbd>K</kbd> has a **Tags** bar and understands `#tag`, finding requests by their tags and collections by theirs or by what is inside; each request's tags are shown after its URL.
- **Tags in History and the command palette:** History has the same **Tags** bar, to see only what was sent from requests with a tag, and its search matches `#tag`. In the command palette, `#smoke` lists **Show requests tagged smoke**, **Run requests tagged smoke**, **Show history tagged smoke**, and an **Open** command for each tagged request; **Clear tag filters** resets them all.
- **Run by tag:** the Runner's **Requests** panel lists the collection's tags; click one to run only requests with it, again to leave them out, with **Any tag** or **All tags** for several. The Run plan and reports show the filter. See [Run by tag](runner.md#run-by-tag).
- **Command line:** `run --tag smoke` (repeatable, or `a,b`), `--all-tags`, and `--exclude-tag slow` choose requests by tag; a mistyped tag stops with a suggestion. `list` takes the same options and shows tags, `request show` shows them, and `request create --tag` adds them.

### Captures and variables

- The Source suggestions fit on one row each, with an icon for what each reads, the body's format as a tag, and the value on the right; their headings count their entries.
- **The capture Source, checked and explained:** a badge says what each source reads; mistakes are flagged before sending — unknown sources and transforms, invalid paths and regular expressions, missing timing or certificate fields — with a one-click fix for a likely slip (**Use jwt** for `jwtt`). The preview shows the value's type and size with **Copy**, and a chain of transforms opens into its **steps**, each with its value. Suggestions are grouped under headings, with the keys at the foot.
- **Dotted capture sources:** `body.user.id` reads the response body as data whatever it is written in — JSON, XML (attributes as `@name`), YAML, form-encoded, NDJSON, or CSV — with JSON path rules (`body.items[*].id`, filters). `header.x-request-id`, `cookie.session` (`cookie["a.b"]` for dotted names), `status.code`, and `status.text` work beside the older spellings, and `$.path` now reads XML and YAML bodies too. Autocomplete offers them first, with each path's format and value. See [Capture values from responses](variables.md#capture-values-from-responses).
- **Vars tab:** a capture's **Source** autocompletes as you type — the kinds of source, then the last response's JSON paths (with their values), headers, cookies, and form fields, then transforms after `|` — and previews what it captures, or why it misses, with secret-looking values hidden. **Suggested from the last response** adds tokens, ids, and request-id headers in one click, and the **Source reference** adds any example as a new capture. See [Capture values from responses](variables.md#capture-values-from-responses).
- Capture from far more of a response: JSON paths with wildcards, negative indexes, and filters such as `$.users[?(@.role == "admin")].id`; regular expressions; text between markers; form fields; cookies; HTML elements and attributes (`html input[name="csrf"] @value`); network timing (`timing ttfb`); the TLS certificate (`certificate days-left`); and a failed request's `error`. See [Capture values from responses](variables.md#capture-values-from-responses).
- Transforms after `|`: `first`, `last`, `length`, `join`, `trim`, `lower`, `upper`, `regex`, `between`, `json`, `jwt`, `base64-decode`, `url-decode`, and `default`.
- Right-click to capture from every response view — body, preview, headers (table and raw), cookies, tests, timeline, comparison, and certificate. See [Capture from a response](responses.md#capture-from-a-response).
- When a request fails, captures that read the failure (`error`, `timing`, `certificate`) still run.
- **More capture transforms:** `at`, `split`, `slice`, `unique`, `sort`, `reverse`, `keys`, `values`, `replace`, `prefix`, `suffix`, `base64-encode`, `url-encode`, `sum`, `min`, `max`, `avg`, `round`, `add`, `subtract`, `multiply`, `divide`, `date`, `epoch`, `epoch-ms`, and `if-empty` — for example `$.items[*].price | sum | round 2`. Autocomplete, the source reference, and the checks as you type know them all. See [Transforms](variables.md#transforms).

### Tests

- Every text comparison for headers, bodies, and JSON strings: `not-equals`, `not-contains`, `starts-with`, `ends-with`, case-insensitive matches, and regular expressions.
- `between` ranges for timing, size, lengths, and JSON numbers; `in` and `not-in` lists; array membership; `body-length`; and JSON Schema validation with `json-schema`. See [Tests](tests.md#comparisons).
- **More test checks:** response cookies (`cookie-exists session`, `cookie theme equals "dark"`), network timing (`timing ttfb < 300`), and certificate expiry (`certificate-days-left > 30`), each in the visual builder too.
- **More test comparisons:** `not-starts-with` and `not-ends-with`; format checks `is-uuid`, `is-email`, `is-url`, `is-date`, `is-number`, `is-integer`, `is-empty`, and `is-not-empty` for headers, cookies, and JSON values; and for JSON arrays `contains-all`, `contains-any`, `is-unique`, `is-sorted`, and `is-sorted-desc`. See [Comparisons](tests.md#comparisons).

### Scripts

- **Request scripts:** a request's new **Scripts** tab runs JavaScript before it is sent and after its response arrives, with the `aw` API — read and set variables, change the URL, method, headers, or body, sign requests with `aw.crypto` (hashes, HMAC, random values) and Base64, and test responses with `aw.test` and `aw.expect`. Script tests appear with the request's tests, `aw.log`, `aw.info`, `aw.warn`, and `aw.error` write to the console, and scripts run on every send and in collection runs, with each data row. See [Scripts](scripts.md).
- Scripts run in a separate JavaScript engine (QuickJS) in a process of their own, with no access to files, the network, timers, or the vault, and stop after 2 seconds or 64 MB.
- Scripts that arrive in an import, a teammate's change, or an edit to the workspace's files are **paused** until you review them and choose **Allow scripts** for their collection; scripts you write run at once. The allow list is kept on your computer, outside every workspace.
- The command line runs scripts with `--allow-scripts` and leaves them out with `--skip-scripts`; a run whose requests have scripts asks for one. Without `-e`, values captured in a run are now kept for later requests in the same run, as script variables are.
- Exports in other tools' formats leave scripts out, with a warning.
- **Collection and folder scripts:** a collection, and each folder in it, can have pre-request and post-response scripts that run for every request inside — outermost first, then the request's own. Pick the level in a request's **Scripts** tab; the tab shows the order they run in. See [Workspace, collection, and folder scripts](scripts.md#workspace-collection-and-folder-scripts).
- **Suggestions as you type:** the script editor suggests the `aw` API — members after each dot, with their signatures and what they do — the keys of the request's last JSON response after `aw.response.json().`, variable, module, and header names inside `aw.vars.get('…')`, `aw.require('…')`, and the header functions, and names declared earlier in the script. Members of the other phase are listed last and say where they work. See [Suggestions as you type](scripts.md#suggestions-as-you-type).
- **Syntax errors as you type:** the script editor underlines a syntax error, marks its line, and names it under the editor — **Syntax error on line 3: Unexpected token** — with **Go to line 3**. It checks without running anything, and finds what the script engine would. See [Syntax errors](scripts.md#syntax-errors).
- **Snippets panel:** beside the script editor, over 40 ready-made snippets in eight groups — variables, request changes, dynamic values, response tests, saving values, crypto and encoding, logging, and the library — filtered for the phase or module being written and searchable. Click one to insert it at the cursor. See [Snippets](scripts.md#snippets).
- **Your own snippets:** save code you use often — from the editor's selection — with a title, a description, and where it is offered, under **+** in the **Snippets** panel. Saved snippets are listed first, under **My snippets**, can be edited and deleted, and are shared with everyone in the workspace, team workspaces included. See [Your own snippets](scripts.md#your-own-snippets).
- **Script library:** modules of shared functions, written once under **Scripts → Library** and loaded in any script with `aw.require('name')`. Modules export with `exports` or `module.exports`, can require each other, and are saved as `scripts/<name>.js`. A module from outside the app is paused until allowed, like a script. See [Script library](scripts.md#script-library).
- **Workspace scripts** run before collection scripts for every request in the workspace. Pick **Workspace** in a request's **Scripts** tab. In a team workspace they are shared with the team, and paused for teammates until allowed.

### History

- History keeps each response's cookies, timing, and certificate, and each send's console lines, and shows them with **Preview**, **Compare**, and **Tests** tabs. A failed request shows its error and what it got through. Everything there can be captured into the request. See [History](history.md).
- Clearing request history asks you to confirm first.

### API specifications and mock servers

- [API specifications](api-specs.md): OpenAPI 3 and Swagger 2 with live validation, formatting, collections generated from a spec, and specs created from a collection.
- [Mock servers](mock-servers.md) on localhost, from routes, collections, or specs — started from the Mocks screen, a spec, or the Docs page. Routes have method pickers, request rules, response rules, response headers with suggestions, Faker-style templates, configurable CORS, default security headers, HTTPS, and a detailed request log. Routes can also stream over [WebSocket, SSE, NDJSON, and gRPC](mock-servers.md#live-protocols), with timed and repeating messages, replies, and gRPC served from a `.proto` schema. Routes can [validate requests](mock-servers.md#validation) — required values and a JSON Schema for the body, filled in from specifications — and answer failures with 422 and the problems.
- **Mocks and their collections stay in step, both ways:** a route added to a mock server made from a collection is added to the collection as a request, and a request added to the collection — made, copied, imported, from cURL or a specification, in the app, VS Code, or the command line — becomes a route on the mock; changing either's method, path or URL, or name changes the other, unless it was changed on its own, and renaming the collection keeps it the mock's. The mock's header says whether they are in step, and **Sync now** (`mock sync`) adds what is missing on both sides. Copies get their own; removing either keeps the other; a running mock serves the change. See [Create a mock server](mock-servers.md#create-a-mock-server).
- **Create an API specification from a mock server:** **Create specification** on a mock's **API docs** tab, or **Create API specification** in its menu, saves the mock's routes as an OpenAPI 3.0.3 specification and opens it in APIs. See [Create a specification](api-specs.md#create-a-specification).
- **Socket.IO routes:** a mock serves Socket.IO at `/socket.io` on its port. A route takes connections to a namespace, emits its messages as named events, and answers each event, or its acknowledgement, with the reply. Handshake rules can check the auth payload.
- **MQTT routes:** a mock runs an MQTT 3.1.1 broker on its own port (and over WebSocket at `/mqtt`). A route publishes its messages to clients that subscribe to its topic, with `:name` levels as parameters, and replies on `<topic>/reply` to messages published to it.
- **TRACE and CONNECT routes:** routes can answer TRACE, and CONNECT by its `host:port` target, so a proxy's answers can be tried locally.
- **Server settings** are a row of tiles, each with its state in words and its key value, and one panel under them for the setting you open, so the routes stay in view. The card's header counts the settings on and those needing attention, such as missing security headers or gRPC routes without a schema. CORS fields are grouped by who can call and what browsers get, and <kbd>Esc</kbd> closes the open setting. See [Server settings](mock-servers.md#server-settings).
- Socket.IO and MQTT requests become routes in **New from a collection**, and their routes become requests when a mock is saved as a collection. See [Mock servers](mock-servers.md#live-protocols).
- **More mock rule comparisons:** rules can check a request's **Cookie**, and compare with equals or does not equal in any case, contains or does not contain in any case, contains all of, contains any of, equals the number, is not the number, and whether a value is Base64, hexadecimal, a JWT, uppercase, or lowercase. **is a date** needs a date that exists on the calendar, so `2026-02-30` does not pass. See [Request rules](mock-servers.md#request-rules).
- A mock route's **Try it** command opens in a new terminal, at the prompt and ready to run.

### Realtime protocols

- [WebSocket](websocket.md), [Server-Sent Events](sse.md), [NDJSON](ndjson.md), and [gRPC](grpc.md) with every kind of streaming, in the same editor as HTTP.
- **Socket.IO** requests: connect to a namespace, see every event the server emits with its name, emit JSON or text as any event, and wait for acknowledgements. See [Socket.IO](socketio.md).
- **MQTT** requests: connect to a broker over `mqtt://`, `mqtts://`, `ws://`, or `wss://` with MQTT 3.1.1 or 5, subscribe to topic filters with their own QoS in **Topics**, and publish with QoS and retain. Basic auth becomes the broker username and password. See [MQTT](mqtt.md).
- **Code** generates Socket.IO clients for Node.js, the browser, and Python, and MQTT clients for mosquitto, Node.js, and Python.
- The protocol playground adds a Socket.IO server and an MQTT broker, and **Use local sample** connects to them.

### Authorization and secrets

- An encrypted [credential vault](credentials.md) backed by the macOS Keychain, Windows DPAPI, or the Linux secret service. Where the vault is locked or refused, the error links straight to the fix.
- [Client certificates](client-certificates.md) are stored in the vault.
- [OAuth 2.0 discovery](authentication.md#oauth-20) from `/.well-known/oauth-protected-resource`, `/.well-known/oauth-authorization-server`, and `/.well-known/openid-configuration`, with RFC 8707 resource indicators.
- Signed JWT bearer tokens are reused until shortly before they expire, so a new token isn't signed for every request.
- [NTLM, WSSE, Akamai EdgeGrid, and Hawk](authentication.md#signed-and-negotiated-types) authentication, inline or as saved credentials in the vault.

### Runner and Interceptor

- The [Runner](runner.md) runs collections, benchmarks, and performance tests, with percentiles, confidence intervals, charts, and saved baselines.
- **A redesigned Runner:** a **Run plan** beside the setup says what the run will send (such as _10 requests (5 × 2)_), against which collection and environment, and what it passes by, with Run, **Stop after the first failure**, and a progress bar in one place. Results open with a verdict that names any missed criterion, five key figures marked when their criterion fails, and **Overview**, **Requests**, **Samples**, **Data rows**, and **Errors** tabs in place of one long page. Latency and reliability are tables instead of lines of numbers. See [Results](runner.md#results).
- **Data-driven collection runs:** choose a CSV, JSON, YAML, or XML file in **Runner → Data file**, and the collection runs once per row, with each column available as `{{column}}` in requests and tests. A preview shows the columns and first rows before you run, and **Data rows** shows which rows passed. See [Run with a data file](runner.md#run-with-a-data-file).
- **Data file:** drop a file on the Runner's **Data file** panel, or choose one. Once loaded, a card shows its name, format, rows, columns, and size with **Replace…** and **Remove**, and each column says whether the selected requests use it (**Used ×1**, **Not used**).
- The [Interceptor](interceptor.md), a capture proxy, records traffic from browsers, simulators, and command-line tools, including decrypted HTTPS, and saves it as requests.

### Saving

- **Auto save options:** in **Settings → Saving**, save after every change (as before), after a pause in editing, or only when you press <kbd>⌘ S</kbd>. With auto save off, the status bar shows **Unsaved changes** to save with one click, closing the window asks to save, discard, or cancel, and switching workspaces asks first. Changes still waiting are always saved before the app closes. See [Saving](settings.md#saving).
- **A default folder for workspaces:** choose where new workspaces and their collections are saved, each in a folder of its own named after it; without one, they stay in the app's data folder. When creating a workspace, **Save in** can pick app data or another folder for it. Credentials stay in the app's data folder, and removing a workspace saved in your own folder keeps its files.
- <kbd>⌘ S</kbd> saves the workspace and says **Workspace saved**.

### Team workspaces

- Work on a workspace with your team through a folder you all can reach — a network drive, Dropbox, OneDrive, Google Drive, iCloud, or a Git checkout — with no account or server. In the workspace manager, choose **Team**, then **Share this workspace…** or **Open team folder…**. See [Team workspaces](team-workspaces.md).
- Collections, environments, API specifications, mock servers, and everyone's history are shared. Secrets stay on each device: saved credentials, inline tokens and passwords, and typed-in values of secret-looking headers, parameters, and variables. Tabs, the selected environment, and preferences are personal.
- Teammates' changes appear within seconds, with a notice naming the requests that changed. Their initials show next to the workspace name, and a request's heading says when someone else has it open.
- History shows teammates' sends with their name. Your limit and **Clear history** apply to your own entries only.
- **Git sync:** share a team workspace through GitHub, GitLab, Bitbucket, or any Git server. **Team → Clone…** clones a repository and opens its team workspace (or shares yours into it); **Git sync** in the workspace's details connects a folder to a remote and commits, pulls, pushes, or syncs it. Git signs in with your SSH key or credential manager; the app never holds a token. When both sides changed a file, the pull is undone and you choose **Keep mine** or **Take theirs**. See [Share through GitHub, GitLab, or Bitbucket](team-workspaces.md#share-through-github-gitlab-or-bitbucket).

### Import and export

- **Import from a link:** paste a gist, a GitHub, GitLab, or Bitbucket file link, or any URL to a collection or specification, and preview it before importing. See [Import](import-export.md#import).
- **Publish to GitHub Gist:** export a collection or the workspace as a secret or public gist, and publish again to update it. The GitHub token is kept in the credential vault and works with GitHub Enterprise Server. See [Publish to GitHub Gist](import-export.md#publish-to-github-gist).
- **Copy an export** to the clipboard instead of downloading it.
- A redesigned import and export dialog: **Files**, **Link**, and **Paste** tabs, drag and drop, a preview that counts what was found and lists requests by collection, and an export summary with its size, what is left out for safety, and a **Preview contents** view of what will be shared.
- Postman collections whose URLs have a port, such as `http://localhost:8080/users/:id`, import with the port intact.

### Command line and CI

- **File uploads from the command line:** `request send --binary-file <path>` sends a file as a request's body, and `--form-file <field>=<path>` the file for a form's file field, instead of being refused; `run --uploads <file>` gives a run each request's files from JSON; `request update --body-type binary`, `--binary-name`, and file fields in `--form-fields` set them up. See [Send a request](cli.md#send-a-request).
- **Client certificates from the command line:** `certificate add` keeps a client certificate (PEM files, or a PFX/P12 bundle with its passphrase from an environment variable) in the vault for a host, and `run` and `request send` present it over mutual TLS, as the app does; `certificate list`, `enable`, `disable`, and `remove` look after them, and `trust` and `untrust` the workspace's CA certificates. `request send --json` includes each hop's timing and the server's TLS connection and certificates. See [Client certificates](cli.md#client-certificates).
- **`environment update`:** saves an environment's whole list of variables from JSON in an environment variable — in order, each on or off, hidden values kept — so values stay off the command line. See [Environments](cli.md#environments).
- **Credentials of every kind:** `secret set` saves bearer, basic, API key, digest, JWT, AWS, OAuth 1.0, NTLM, WSSE, EdgeGrid, Hawk, and OAuth 2.0 credentials, with `--fields-from-env` for each kind's settings and secrets as JSON in an environment variable, and changes one by name, keeping the secrets not given. `secret list --json` shows each one's settings, never its secrets. See [Saved credentials](cli.md#saved-credentials).
- **Edit mock routes:** `mock update` changes a route's method, path, name, response headers, and body, adds routes with them, and removes routes (`removeRoutes`); `mock show --json` gives each route's headers, secret-looking values hidden, and body. See [Mock servers](cli.md#mock-servers).
- **`mock update`:** changes a mock server's name, port, CORS, default headers, HTTPS files, gRPC and MQTT ports, and its routes' switches, statuses, and delays from a JSON file, shaped as `mock show --json` gives them under `settings`. See [Mock servers](cli.md#mock-servers).
- **Switch headers off and on:** `request update --disable-header <name>` keeps a header in the request without sending it, and `--enable-header <name>` sends it again. See [Collections and requests](cli.md#collections-and-requests).
- **`request schema`:** asks a GraphQL request's endpoint for its schema with an introspection query, sent with the request's URL, headers, auth, and environment, without saving or running scripts; `--json` prints its types and fields. See [Collections and requests](cli.md#collections-and-requests).
- **Team folders keep auth secrets with the app:** a token, password, or other auth secret set from the command line or VS Code for a team folder the app on this computer has open is kept with the app's own data for it, never in the folder, and used by later sends. For a folder the app does not have, it is refused rather than silently lost. See [Team folders in Git](vscode.md#team-folders-in-git).
- **Every auth type from the command line:** `request update --auth` takes jwt, aws, oauth1, oauth2, ntlm, wsse, edgegrid, and hawk, and `--auth-fields-from-env <VAR>` sets each type's settings and secrets from JSON in an environment variable, never an argument. `request token` gets a request's OAuth 2.0 access token and keeps it in the request without printing it. See [Collections and requests](cli.md#collections-and-requests).
- **`request connect`:** opens a WebSocket, gRPC, SSE, NDJSON, Socket.IO, or MQTT request — with its saved credential, from a vault with a password (`API_WORKBENCH_VAULT_PASSWORD`) — and keeps it open, printing each event as it happens and sending each line of standard input as a message; `--json` makes both JSON lines. See [Command line](cli.md).

### Security

- **The terminal is kept apart from the app's page:** the terminal on the Terminal tab of dev tools is now a page of its own, drawn over the panel — the only page the main process takes shell input from, in a session of its own — so nothing the app's window shows (responses, previews, imports from anywhere) can type into a shell. **Open in new window** moves it, shells and all, into a window of its own, and **Return to panel** puts it back. **Run in terminal** stages a command at a new terminal's prompt, cleaned of line breaks and control characters by the main process too, for you to run. Tabs, splits, shells, and shortcuts work as before. See [Terminal](dev-tools.md#terminal).
- **The Interceptor's certificate covers only the sites you test:** **Domains to decrypt**, required with **Decrypt HTTPS** on, writes X.509 name constraints into the Interceptor's certificate, so it can vouch only for those domains, their subdomains, and this computer — a copy of its key could not impersonate any other site. HTTPS to other hosts passes through unread, and the trust confirmation says what the certificate covers. A certificate from an earlier version, which could vouch for any site, is replaced the next time decryption starts. See [HTTPS decryption](interceptor.md#https-decryption).
- **The Interceptor asks first, where no page can answer:** starting HTTPS decryption and trusting the Interceptor's certificate are confirmed in a native dialog shown by the app itself, so nothing displayed in the window can read HTTPS traffic without you. The Interceptor's certificate now lasts 30 days instead of ten years and is renewed as it runs out; a ten-year one from an earlier version is untrusted and replaced the next time HTTPS decryption starts. See [Interceptor](interceptor.md).
- **VS Code asks before a `.http` file or team folder sends to a new host:** the first send from a workspace's `.http` files or team folders to each host — checked after `{{variables}}` are filled in — asks **Send to api.example.com?**, with **Always Allow This Host** to remember it for the workspace; a run or the Runner asks about every new host before it sends anything, worked out from its environment and data file (`run --list-hosts`), and asks afterwards only about a host an earlier response's capture supplies; a live request (WebSocket, gRPC, SSE, NDJSON, Socket.IO, MQTT) asks before it connects. Requests to this computer and from the app's own workspaces never ask; **API Workbench: Forget Approved Hosts** starts over, and `apiWorkbench.confirmNewHosts` (user settings only) turns it off. See [.http files](vscode.md#http-files).
- **`run --list-hosts`:** prints, as JSON, the hosts a run's requests would go to — for every data row, with the environment and `-v` values — and sends nothing; requests whose host comes from an earlier capture are listed as `unresolved`. See [Command line](cli.md).
- **`--allow-host` on the command line:** `request send`, `run`, and `request connect` send or connect only to the hosts named (`*.example.com` for subdomains), checked after variables and pre-request scripts; a request to any other is not sent. In CI it keeps a run on the environment you meant. See [Command line](cli.md).
- **Fuzzing in CI:** every push fuzzes the parsers that read other people's text — importers, `.http` and cURL files, specifications, assertions, response bodies, and regular expressions — and fails on a crash, a hang, a memory blow-up, or a changed prototype, keeping the input that caused it (`npm run test:fuzz`). Its first run found a crash in the VS Code extension's `.http` reader, now fixed.
- **Shared request files cannot send files from outside their project:** a file that a `.http` file names (`< ./path`) must be inside the repository it is in — the nearest folder above it with `.git`, or its own folder outside a repository. An absolute path elsewhere, `../` above the repository, or a link pointing out of it (such as to `~/.ssh`) is refused before anything is sent, so opening a repository and clicking **Send Request** can no longer upload your keys or other files to the address its requests name. `../fixtures/data.json` inside the repository still works, and `--binary-file`, `--form-file`, `--uploads`, and files chosen in VS Code's file dialog still send any file you choose yourself. See [Send a request](cli.md#send-a-request).
- **Regular expressions cannot hang the app:** a test, `regex` capture, mock rule, mock path parameter, or JSON Schema `pattern` that could take minutes to match — such as `body matches /(a+)+$/` against a short response, or a mock rule that any web page could trigger by sending a request to the mock — is now refused when it is used, with the reason and how to write it instead, rather than freezing the app, a run, or a mock server. Patterns from the documentation and examples are unaffected. See [Tests](tests.md).
- **Found by fuzzing and code scanning:** API Workbench's importers, `.http` and cURL parsers, specification checks, assertions, and mock rules were run against millions of malformed inputs, and the code was scanned with CodeQL's security queries; what they found is fixed.
- **Outside links stay web links:** every link the app opens outside itself — from a response, a guide, or an OAuth sign-in page — goes through one check that passes only `http:`, `https:`, and `mailto:`, so a collection cannot make the system open `file:`, `smb:`, `ms-msdt:`, or another program's link. The documentation site now sends a content security policy that allows only its own scripts, styles, and images.
- **Dependencies up to date:** every package is on the newest minor and patch versions of its dependencies, including Electron 45.2.3 (with Chromium's latest security fixes), Vue 3.5.45, Vite 8.3.7, Tailwind CSS 4.3.5, undici 8.12.4, `electron-updater` 6.8.12, `ws` 8.22.2, `jose` 6.2.17, `marked` 18.2.0, and the AWS SDK; `form-data` stays at its patched 4.0.6 everywhere.
- **Scripts cannot move a request to another host:** if a request's pre-request scripts change where it goes — by assigning `aw.request.url` or by setting a variable its URL uses — it is not sent, in the app, the Runner, and the command line. An allowed script can still change the path, query, headers, and body. See [What scripts can reach](scripts.md#what-scripts-can-reach).
- **Replacing the Interceptor's certificate removes the old one's trust:** **New certificate** first removes a certificate you trusted with **Trust certificate** from your trusted certificates, so a replaced certificate can no longer be used to read your HTTPS traffic. See [Interceptor](interceptor.md).
- **Notarized, tighter macOS builds:** signed macOS releases are notarized by Apple, and run with only the JIT entitlement: library validation is on, so the app loads only code signed with its own identity.
- **API Workbench vault:** where the system has no credential store (such as Linux without a keyring), credentials are kept in API Workbench's own vault instead of not at all — encrypted with AES-256-GCM under a key protected by a vault password you choose and a recovery key you save once. It locks after 15 minutes without use; errors that need it ask for the password in place; **Forgot your password?**, **Change password**, and **Reset vault…** are on the Credentials screen. See [The API Workbench vault](credentials.md#the-api-workbench-vault).
- Security: every permission except the clipboard is refused, no web content can open windows, navigate, or attach a `<webview>`, and the content security policy also blocks plugins, forms, and `<base>`. Commands put in the terminal cannot run themselves, and copied cURL and `grpcurl` commands quote every value. `form-data` is pinned to 4.0.6 for the code generator, fixing a CRLF-injection advisory.
- Security: the main process answers only the app window's top frame, the desktop page cannot open network connections itself, and CI now audits dependencies, runs CodeQL, scans the git history for secrets with gitleaks, and receives weekly Dependabot updates.
